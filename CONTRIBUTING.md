# Contributing to LAND INTELLIGENCE

## Development Workflow

LAND INTELLIGENCE uses a branch-based workflow for changes:

1. Start from the latest `main` branch.
2. Create a dedicated branch for the change.
3. Make and test the change.
4. Commit the change with a clear commit message.
5. Push the branch to GitHub.
6. Open a pull request targeting `main`.
7. Review the changed files and checks.
8. Merge the pull request after review.
9. Delete the short-lived feature branch after the merge when it is no longer needed.

## Pull Request Expectations

Pull requests should:

- Clearly describe what was changed.
- Keep the scope focused.
- Avoid introducing unsupported claims about land records or government systems.
- Preserve the project's human-in-the-loop approach.
- Use synthetic, anonymized, public, or properly permitted demonstration data.

## Prototype Safety

LAND INTELLIGENCE is a student-developed prototype. Anomaly detection and prioritization are intended to support human verification and should not be presented as automatic legal, ownership, title, fraud, or land-status determinations.
